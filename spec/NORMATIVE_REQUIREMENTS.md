# Normative requirements

The NIP draft remains authoritative. This index provides stable implementation anchors.

- **NCRDT-SCOPE-001** — The key words MUST, MUST NOT, SHOULD, SHOULD NOT, and MAY are to be interpreted as described in RFC 2119 and RFC 8174. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-NIP01-001** — Clients MUST validate the event id and Schnorr signature according to [NIP-01](01.md) before processing any event defined here. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-NIP01-002** — A parser used for this NIP MUST reject duplicate top-level JSON member names. All public keys, event ids, change hashes, and SHA-256 values defined here MUST be 64 lowercase hexadecimal characters. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-NIP01-003** — `created_at`, relay arrival order, subscription order, relay URL, and transport path MUST NOT determine document state, control order, authorization, checkpoint selection, or conflict resolution. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-ACQ-001** — The acquisition channel MUST NOT change validation or document state. A client that republishes a carrier MUST preserve the complete signed event. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-TAG-001** — Every required tag defined here MUST appear exactly once and MUST contain exactly the elements shown in its event definition. A required tag is invalid when it is missing, repeated, missing a value, contains extra elements, or has a malformed value. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-TAG-002** — Tag order does not affect protocol meaning. Unknown tags MUST be ignored and MUST NOT change v1 state. An extension that changes identity, authorization, dependencies, or state requires a new protocol version or event kind. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-TAG-003** — Durable events of kinds `1624`, `1625`, `1626`, `1627`, and `31624` MUST NOT contain a [NIP-40](40.md) `expiration` tag or the [NIP-70](70.md) protected-event `-` tag. Other authorized devices may need to preserve and republish the same signed history. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-JSON-001** — The `content` of manifests, controls, checkpoint descriptors, and checkpoint chunks MUST use the JSON Canonicalization Scheme defined by [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785). _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-JSON-002** — A v1 decoder MUST reject: _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-JSON-003** — Arrays declared as sorted MUST already be sorted. Consumers MUST NOT repair signed content before validation. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-B64-001** — Binary content MUST use standard RFC 4648 base64 with padding. URL-safe, unpadded, whitespace-tolerant, and non-canonical forms are invalid. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-LIMIT-001** — A conforming v1 client MUST accept valid objects up to these limits: _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-DOC-001** — Clients SHOULD share public documents using a [NIP-19](19.md) `naddr` for the manifest, with relay hints where useful. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-ACTOR-001** — Each editing installation MUST use a distinct device key. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-ACTOR-002** — A removed device key MUST NOT appear in a later control. Reinstatement, device replacement, or privilege elevation uses a fresh device key and therefore a fresh ActorId. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-ACTOR-003** — A device key SHOULD NOT be active on more than one installation. If a key is cloned, the equivocation rules below protect convergence but cannot restore confidentiality or trust. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-FRAME-001** — Before invoking an Automerge parser, a client MUST validate this framing: _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-ENC-001** — A valid change MUST decode and encode to the same bytes: _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-ENC-002** — Equivalent APIs may be used. The result MUST match the language-neutral v1 test vectors. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-SEM-001** — The v1 Automerge profile uses 32-byte actors, UTF-16 code-unit text indexing, time 0, no message, empty extra bytes, the listed v1 action/object/scalar/column/mark semantics, and treats unknown semantics in a declared v1 object as invalid. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-SEQ-001** — All arithmetic MUST be checked for overflow. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-SEQ-002** — For `seq > 1`, the accepted dependency closure MUST contain exactly one accepted change from the same actor with `seq - 1`. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-FANIN-001** — A control frontier contains at most 64 heads. When a document has more heads, an authorized writer SHOULD create empty Automerge merge changes before the control is issued. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-FANIN-002** — A merge change may contain at most 256 dependencies. Producers SHOULD sort heads by decoded ChangeHash bytes and build a bounded fan-in chain until the final frontier contains at most 64 heads. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-MANIFEST-001** — - `control` SHOULD be the canonical control tip known to the controller and MUST name a valid control event for this coordinate; - `checkpoint` is `null` or one advisory checkpoint descriptor event id; - `format` is `automerge-change-v1`; - `text_encoding` is `utf16`; - `status` is `active`, `frozen`, or `superseded`; - `successor` is `null` or a document coordinate; - `relays` contains at most 16 unique absolute `ws` or `wss` URLs, sorted by UTF-8 bytes; - `name` is `null` or at most 256 UTF-8 bytes; - `description` is `null` or at most 2,048 UTF-8 bytes; and - `application` is `null` or the object shown above, where `id` is printable ASCII of at most 128 bytes, `schema_version` is at most 64 UTF-8 bytes, and `schema_hash` is `null` or one SHA-256 value. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-MANIFEST-002** — The latest manifest is selected according to NIP-01 before manifest validation. If the selected event is invalid, the manifest is unavailable. Clients MUST NOT fall back to an older manifest because a relay may already have discarded it. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CONTROL-001** — - `seq` starts at `0` and increases by one; - genesis has no parent and an empty `base_heads` array; - `format`, `text_encoding`, and `policy` are fixed for the document; - members are sorted by decoded device pubkey bytes and contain no duplicate device key; - `account` is `null` or one Nostr public key and is fixed from the device's first appearance; - roles are sorted, unique, non-empty, and contain only `checkpoint` and `write`; - `write` authorizes change events; - `checkpoint` authorizes checkpoint descriptors and chunks; - the controller has no implicit device role; - an existing device's later role set MUST be a subset of its earlier role set; - a removed device key MUST NOT reappear; - `base_heads` is sorted by decoded hash bytes, unique, an antichain, and contains at most 64 hashes; - every base head is accepted under the parent control; - for every writer retained from the parent control, the base closure contains that ActorId's highest accepted change in the parent accepted state; - `predecessor` is `null` except on genesis; - `successor` is `null` unless the control is terminal; and - a control is terminal when no member has `write`. A terminal control has no valid child. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CHAIN-001** — A newly received lower-id sibling may change the canonical chain. Clients MUST retain signed evidence and rebuild derived state when this happens. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-BARRIER-001** — A producer MUST durably persist the exact signed control before signing a change or checkpoint that references it. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-BARRIER-002** — A producer SHOULD publish the control before publishing dependent carriers. A client that receives a dependent carrier before its control MUST retain the carrier as pending. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-BARRIER-003** — After a dependent carrier has been signed, additional control durability MUST be obtained by republishing the same signed control event. The controller MUST NOT create a semantically equivalent control with a different event id and treat it as the same authorization epoch. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-DUP-001** — Clients SHOULD retain at least one complete valid carrier for every accepted ChangeHash. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-EQUIV-001** — Clients SHOULD preserve equivocation evidence and prompt the controller to revoke the device. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-STATE-001** — Clients MUST rerun this process from genesis when new evidence can change a control choice, dependency, or equivocation result. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-STATE-002** — Implementations may optimize storage and traversal. They MUST produce the same canonical controls, accepted ChangeHashes, excluded ChangeHashes, heads, and materialized document. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-OUTCOME-001** — Clients SHOULD keep these local outcome categories distinct: _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CHECKPOINT-001** — Checkpoint publication is optional. A conforming client MUST support ordinary change replay when no checkpoint is available. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CPDESC-001** — The snapshot MUST be one complete Automerge `save()` made after closing pending transactions. Incremental saves and bundles are invalid. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CPDESC-002** — `heads` MUST be sorted, unique, and equal the heads obtained after loading the snapshot. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CPDESC-003** — The loaded change set MUST equal exactly the ancestor closure of `heads`. Extra disconnected changes make the checkpoint invalid. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CPDESC-004** — `raw_size` MUST be greater than zero. `chunk_size` MUST be between `1` and `32768`. `chunk_count` MUST equal `ceil(raw_size / chunk_size)` and MUST be between `1` and `4096`. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CPDESC-005** — The declared heads and all embedded changes MUST be accepted no later than the referenced control. A checkpoint MUST NOT include state authorized only by a later control. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CPDESC-006** — All declared counts and limits MUST match the loaded snapshot. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CPCHUNK-001** — The index, count, chunk size, chunk hash, proof, and descriptor root MUST validate. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CPCHUNK-002** — All non-final chunks MUST have the descriptor `chunk_size`. The final chunk contains the remaining bytes. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CPCHUNK-003** — After assembly, the client MUST verify: _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CPTRUST-001** — Every change embedded in a usable v1 checkpoint MUST have at least one valid carrier and the client MUST verify the full control chain, signatures, actors, counters, dependencies, frontiers, and equivocation rules. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CPTRUST-002** — Checkpoint parsing SHOULD use bounded memory and deterministic work budgets. Local budget exhaustion is not proof that a checkpoint is invalid. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-BACKFILL-001** — Clients SHOULD open a live subscription before, or together with, historical backfill. All received events are deduplicated by Nostr event id. Document changes are additionally deduplicated by ChangeHash. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-BACKFILL-002** — Clients SHOULD use [NIP-77](77.md) when available. NIP-77 reconciles event ids; actual carriers still move through ordinary `EVENT` and `REQ` messages and are validated by this NIP. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-BACKFILL-003** — A plain `EOSE` marks the stored/live boundary. It does not prove that a relay returned every matching stored event. Clients SHOULD use [NIP-67](67.md) hints when available and otherwise continue bounded pagination and dependency recovery. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-STATUS-001** — A client MUST NOT claim global finality. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-PUB-001** — Producers SHOULD coalesce high-frequency local edits into bounded Automerge changes. They SHOULD publish at meaningful durability or interaction boundaries rather than publishing one event for every keystroke, pointer movement, or transient UI action. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-PUB-002** — A local commit MUST NOT wait for relay publication. Clients SHOULD durably persist signed carriers in a local outbox before network publication. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-PUB-003** — Retries are idempotent by event id. Clients SHOULD publish durable carriers to more than one independently operated relay and SHOULD read back important controls and checkpoint objects by exact event id. _(source: `specs/NIP_DRAFT.md`)_

- **NCRDT-RELAY-001** — A suitable relay SHOULD: _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-RELAY-002** — Clients MUST NOT treat a relay's [NIP-11](11.md) declaration as proof of complete history, permanent retention, checkpoint availability, or CRDT validation. Relays implementing [NIP-77](77.md) advertise that capability separately. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-RELAY-003** — Relays MAY require [NIP-42](42.md), payment, proof of work, or other local admission policy. Relay admission does not change document validity. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-RETENTION-001** — Relays are not required to retain complete document history indefinitely. Producers SHOULD use local durable storage and more than one retention domain. They SHOULD create a successor document before a document approaches the v1 resource limits or when its retention, privacy, membership, or governance boundary must be reset. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-APP-001** — Application rules MUST NOT change the core control chain, accepted ChangeHashes, or Automerge heads defined by this NIP. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-APP-002** — Large binary objects SHOULD be stored outside the Automerge document. The document may contain hashes and metadata for those objects. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-VERSION-001** — A client MAY retain an unknown protocol revision or unknown Automerge profile as `unsupported_revision` evidence but MUST NOT apply it. Known-v1 unknown semantics are invalid. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-SECCTRL-001** — Controller keys SHOULD be kept separate from routine editing keys and SHOULD have a tested recovery procedure. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-RESOURCE-001** — Clients MUST enforce the v1 limits before large allocations where possible. They SHOULD use bounded workers for Automerge and checkpoint parsing and MUST avoid recursion or work that is unbounded by validated input limits. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CONF-001** — A client claiming v1 conformance MUST pass language-neutral vectors for manifests, controls, changes, causal transitions, forks, equivocation, verified-history checkpoints, dependencies, and randomized delivery. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CONF-002** — Each required vector MUST produce expected canonical controls, protocol dispositions, accepted ChangeHashes, heads, history_digest, dispositions_digest, typed state assertions, and alerts. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CONF-003** — The vectors are maintained outside the NIPs repository and MUST be linked from the proposal before it is marked ready for acceptance. If the prose and a vector disagree, the prose in this NIP controls. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-PROFILE-001** — Implementations MUST treat kinds, limits, encodings, actor derivation, and selection rules as one sealed revision; applications cannot customize them while claiming conformance. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-DISPOSITION-001** — Canonical dispositions are accepted, pending, excluded, invalid, and unsupported_revision. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-COMPLETION-001** — Complete, budget_exhausted, and cancelled are local completion states and MUST NOT alter canonical dispositions or disposition digests. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CPRECOVERY-001** — Recovery from a snapshot whose historical carriers are unavailable is outside v1 and MUST NOT be inferred from a manifest pointer. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-CONF-004** — The initial conformance contract MUST NOT define a digest over Automerge save bytes until independent byte-identical behavior is proven. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-ALERT-001** — Clients MUST surface controller equivocation and canonical-control reorganization as integrity alerts. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-ALERT-002** — Clients MUST surface the first device-equivocated actor sequence and affected changes as an integrity alert. _(source: `specs/NIP_DRAFT.md`)_
- **NCRDT-LIMITS-001** — Draft protocol limits are sealed for the draft revision but remain production-provisional until measured cross-platform qualification. _(source: `specs/NOSTR_AUTOMERGE_V1_SPEC.md`)_
- **NCRDT-REPO-001** — The generic implementation MUST be a standalone snake_case repository/package/crate and MUST NOT depend on radroots_* crates. _(source: `specs/ARCHITECTURE.md`)_
- **NCRDT-CORE-001** — The initial core MUST be deterministic, batch-oriented, network-free, database-free, async-runtime-free, FFI-free, and application-schema-free. _(source: `specs/ARCHITECTURE.md`)_
- **NCRDT-AUTOADAPTER-001** — All Automerge calls MUST be isolated in the anti-corruption adapter. _(source: `specs/AUTOMERGE_PROFILE.md`)_
- **NCRDT-AUTOADAPTER-002** — Every protocol document construction/load MUST explicitly select UTF-16, disable migration, and reject partial load. _(source: `specs/AUTOMERGE_PROFILE.md`)_
- **NCRDT-AUTOADAPTER-003** — The canonical re-encoding path MUST be qualified as bounded, uncompressed, fallible, and cross-language compatible before it is used as a validity rule. _(source: `specs/AUTOMERGE_PROFILE.md`)_
- **NCRDT-NIPBOUNDARY-001** — Public ingestion MUST begin from raw event JSON bytes so duplicate members can be rejected. _(source: `specs/WIRE_FORMAT.md`)_
- **NCRDT-EVIDENCE-001** — Invalid evidence for a ChangeHash MUST NOT poison a valid carrier for that ChangeHash. _(source: `specs/DATA_MODEL.md`)_
- **NCRDT-EVALUATOR-001** — The initial reference evaluator MUST perform deterministic complete batch reconstruction and serve as the oracle for optimized implementations. _(source: `specs/ARCHITECTURE.md`)_
- **NCRDT-FEATURES-001** — Cargo features MUST NOT change protocol validity or conformance semantics. _(source: `specs/VERSIONING_AND_COMPATIBILITY.md`)_
- **NCRDT-TS-001** — The TypeScript implementation MUST be independently written and MUST NOT import or call the Rust implementation. _(source: `implementation/TYPESCRIPT_INTEROP_PLAN.md`)_
- **NCRDT-RESOURCE-017** — Every authoritative epoch semantic check, including writer authorization, actor sequence validation, empty-change frontier validation, and candidate semantic projection, MUST charge and check cancellation immediately before each target-proportional read, comparison, allocation, insertion, or retained-history visit, or reuse an equivalent fully metered projection. _(source: `spec/REPORT_CONTRACT.md`)_
- **NCRDT-RESOURCE-018** — The accepted dependency-closure projection MUST expose the candidate actor expected sequence and the causal next-operation value without an unmetered rescan of the closure or actor-state map. Repeated history-sized scans during candidate validation are prohibited. _(source: `spec/REPORT_CONTRACT.md`)_
- **NCRDT-RESOURCE-019** — Ordinary epoch ancestry classification MUST be nonallocating or explicitly metered and cancellable. When only valid, pending, or invalid is needed, the runtime path MUST NOT construct diagnostic vectors proportional to missing or omitted history. _(source: `spec/REPORT_CONTRACT.md`)_
- **NCRDT-EVIDENCE-007** — A local code-complete claim MUST be backed by a closed runtime operation inventory that enumerates every target-sized helper reachable from the public evaluator and binds each family to exact source, a named executable proof, mutation coverage, candidate identity, command, and passing artifact. An omitted helper invalidates closure. _(source: `spec/EVIDENCE_POLICY.md`)_
